# Spec: 05.4 Datasets Remediation - Dynamic Missions & Compound Faults

## Problem Statement

The XGBoost ML model currently throws severe false alarms during normal transient flight operations (such as sudden throttle spikes or steep climbs) because the existing `loiter` and `takeoff_cruise` mission datasets primarily contain steady-state training examples. Additionally, while the model is being upgraded to detect compound (overlapping) faults, the current dataset generation pipeline only has a random 30% chance to inject a secondary fault. This sparse generation fails to guarantee enough balanced training data for the model to reliably learn compounded physical signatures.

## Solution

The dataset pipeline will be expanded to encompass these edge cases. A new `dynamic_maneuvers.yaml` mission profile will be added to explicitly train the ML models on safe but highly transient engine behavior. Furthermore, the `generate_datasets.py` bulk orchestrator will be updated to explicitly include a `compound` dataset class. This class will force the `FaultScheduler` to guarantee the injection of overlapping faults, ensuring a perfectly balanced distribution for the downstream multi-label classifier.

## User Stories

1. As an ML Engineer, I want the training datasets to include extreme transient maneuvers, so that the XGBoost model learns that sudden throttle/altitude changes are normal and stops throwing false alarms.
2. As an ML Engineer, I want a dedicated subset of guaranteed compound fault datasets, so that the multi-label XGBoost model has sufficient data to learn the overlapping signatures of concurrent failures.
3. As a Data Engineer, I want the `dynamic_maneuvers.yaml` to seamlessly plug into the existing `generate_mission.py` parser, so that I do not have to write custom orchestration logic to support transient profiles.
4. As a Data Engineer, I want the `generate_datasets.py` bulk orchestrator to explicitly dispatch `compound` jobs alongside `healthy` and single faults, so that the final exported parquet partition structure remains balanced and organized.

## Implementation Decisions

- **Modules to be built/modified**:
  - `datasets/missions/dynamic_maneuvers.yaml` (New file)
  - `datasets/generate_datasets.py` (Modified)
  - `datasets/generate_mission.py` (Modified `FaultScheduler` logic)
- **Architectural approach**:
  - The `dynamic_maneuvers.yaml` will adhere to the standard mission schema (phases with `duration`, `throttle`, `altitude`), but will feature very short durations (e.g. 10-30 seconds) alternating between extreme throttle and altitude extremes to induce maximum sensor lag and residual spikes.
  - In the bulk orchestrator (`generate_datasets.py`), the `all_classes` list will append `"compound"`.
  - The `FaultScheduler` (in `generate_mission.py`) will be updated so that if `force_fault_class="compound"`, it actively selects two distinct faults from `KNOWN_FAULTS` and guarantees their injection at 100% probability, rather than relying on the default 30% random chance. 

## Testing Decisions

- **What makes a good test**: Tests should verify the final outputs provided to the ML models (the generated DataFrames and parsed objects) rather than relying on the internal state of the `FaultScheduler`.
- **Modules to be tested**:
  - `tests/unit/test_mission_profiles.py`
  - `tests/unit/test_cascading_faults.py` (or dataset equivalent)
- **Testing Seams**:
  1. **Mission Parsing**: Pass the newly created `dynamic_maneuvers.yaml` to `parse_mission_config()` and assert that it returns a fully valid `MissionProfile` object without raising schema validation errors.
  2. **Pipeline Compound Assertion**: Run the `generate_single_mission` pipeline explicitly requesting the `compound` fault class. Intercept or read the output `pandas.DataFrame` and assert that at some point before the end of the simulation, both `fault_severity` and `secondary_fault_severity` columns are strictly greater than `0.0`.

## Out of Scope

- Refactoring the ML models to consume this new data (handled in Phase 03.3).
- Adding new types of physical faults to the simulation engine (handled in prior simulation phases).
- Modifying how the simulation engine mathematically combines multiple faults (additive offsets are already fully supported in the physics engine).

## Further Notes

- The addition of `dynamic_maneuvers.yaml` will automatically be picked up by the random choice selector in `generate_datasets.py`, so healthy instances of this transient profile will naturally dilute the steady-state data, perfectly addressing the XGBoost false-alarm vulnerability.
