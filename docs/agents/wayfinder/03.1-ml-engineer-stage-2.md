# [wayfinder:task] ML Engineer: Stage 2 (Time-Series RUL & Degradation Models)

## Problem Statement

With the baseline ML pipeline (Stage 1 XGBoost for discrete fault classification and Isolation Forest for anomaly detection) operational, we must now build the core prognostic engine: Remaining Useful Life (RUL) prediction. Discrete classifiers cannot forecast continuous wear or provide confidence intervals for mission safety bounds. We need a recurrent neural network that can digest the temporal degradation patterns over time and output a probabilistic forecast of time-to-failure.

## Solution

We will implement the ML Stage 2: Probabilistic LSTM architecture. The pipeline will be built in PyTorch and will take downsampled telemetry combined with physics residuals as input. The model will output Gaussian distribution parameters ($\mu$ for expected RUL, $\sigma$ for variance/uncertainty) optimized via Negative Log-Likelihood (NLL). It will be designed to run directly within the FastAPI inference process space for the upcoming MVP integration.

## User Stories

1. As an ML Engineer, I want to downsample the raw 10 Hz telemetry and residuals (e.g., to 1 Hz or 0.1 Hz) and window them (60-120 steps) before training, so that the LSTM focuses on long-term wear trends rather than high-frequency noise.
2. As an ML Engineer, I want the feature vector to concatenate both raw telemetry and physics residuals at each timestep, so that the LSTM benefits from both the absolute physical bounds and the baseline deviation context.
3. As an ML Engineer, I want to train an LSTM (Long Short-Term Memory) network, so that I have the expressivity to capture highly complex, non-linear degradation patterns across the mission.
4. As an ML Engineer, I want the LSTM to output a Gaussian distribution ($\mu$ and $\sigma$) trained with a Negative Log-Likelihood (NLL) loss, so that I fulfill the probabilistic RUL requirement.
5. As an ML Engineer, I want the training loop to save the best model weights based on validation loss, so that I can prevent overfitting.
6. As a Mission Commander, I want to know the confidence interval of the RUL prediction ($\mu \pm \sigma$), so that I can make safe operational bounds decisions.
7. As a Backend/Integration Engineer, I want the final compiled PyTorch model to be loadable directly into the FastAPI process space, so that I do not have to manage external inference microservices for the MVP.
8. As a Backend/Integration Engineer, I want the model's inference method to accept a standardized tensor shape `[batch_size, sequence_length, num_features]`, so that I can easily wire the real-time MQTT streams into it.

## Implementation Decisions

- **Recurrent Cell**: LSTM (Long Short-Term Memory).
- **Data Windowing**: Downsampled to 1 Hz or 0.1 Hz; Sequence length of 60-120 steps.
- **Feature Integration**: Concatenation of raw telemetry and physics residuals into a single vector.
- **Probabilistic Output & Loss**: Gaussian output ($\mu$, $\sigma$) trained via NLL.
- **Inference Hosting**: Designed for In-Process hosting within FastAPI, avoiding microservice overhead for the MVP.
- **Dataset Splitting**: Must strictly group by mission ID to prevent time-series data leakage between training and validation sets.

## Testing Decisions

- **Data Preprocessing Seam**: The data loader/windowing function will be tested by passing a mock DataFrame with a known length and frequency. We will assert that the resulting PyTorch tensor has the exact expected shape `[batch_size, sequence_length, features]` and correct downsampled values.
- **Training & Overfitting Seam**: The PyTorch model, NLL loss, and training loop will be tested on a tiny, deterministic "toy" dataset (e.g., 5 simple linear missions). A successful test will assert that the loss decreases significantly over a few epochs and the model outputs a low $\sigma$ on the training data.
- **Inference Interface Seam**: We will test the model's forward pass by instantiating an untrained model, passing a dummy tensor of the expected shape, and asserting it outputs exactly two values ($\mu, \sigma$) without crashing.

## Out of Scope

- Real-time inference integration with the FastAPI backend (this is part of Milestone 4: Integration).
- Hyperparameter sweeps (we will use sensible defaults for the MVP to establish the baseline).
