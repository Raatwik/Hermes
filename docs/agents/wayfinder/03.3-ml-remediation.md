# Spec: 03.3 ML Pipeline Remediation - Multi-Label & Anomaly Fixes

## Problem Statement

Extensive evaluation has revealed critical flaws in the trained Machine Learning models when exposed to real-world complexities. First, XGBoost is currently trained as a single-class predictor (using `multi:softprob`), forcing it to pick only one fault at a time. This causes it to completely mask compound faults (e.g., if Misfire and Lubrication issues occur simultaneously, it only reports one). Second, the Isolation Forest anomaly detector fails completely (0% recall on anomalies) because it was trained on a contaminated dataset containing hundreds of thousands of fault states, stretching its boundary too wide. Finally, the LSTM acts as a static countdown timer because it was trained on non-terminating datasets.

## Solution

The ML pipeline must be overhauled to address these flaws. XGBoost will be wrapped in scikit-learn's `MultiOutputClassifier` to predict multiple overlapping faults simultaneously via a one-hot matrix. The Isolation Forest training script will be hardened to strictly filter out any non-healthy data before fitting, establishing a pure baseline of normal behavior. The LSTM will simply be retrained on the newly updated datasets (generated in Phases 04.3 and 05.4), which inherently fix its countdown timer flaw.

## User Stories

1. As an ML Engineer, I want the XGBoost model to output predictions for multiple concurrent faults, so that compound issues are not masked from the operator.
2. As a Backend Developer, I want the ML Inference API (`inference.py`) to properly parse the new multi-label array output from XGBoost, so that it can return a clean list of all active faults to the frontend.
3. As an ML Engineer, I want the Isolation Forest to fit exclusively on `fault_class=healthy` data, so that its normal boundary is extremely tight and accurate.
4. As an ML Engineer, I want the Isolation Forest `contamination` parameter set to a realistic noise level (e.g., `0.001`), so that it doesn't falsely flag normal sensor noise as an anomaly.
5. As a Data Scientist, I want to execute a clean retrain of the LSTM RUL model on the new, physically-terminating telemetry datasets, so that the model learns the true dynamic degradation curves of the engine.

## Implementation Decisions

- **Modules to be modified**:
  - `ml_pipeline/train_xgboost.py` (Model architecture and target shaping)
  - `ml_pipeline/inference.py` (Output parsing)
  - `ml_pipeline/train_isolation_forest.py` (Data filtering and hyperparameter tuning)
- **Architectural approach**:
  - **XGBoost**: Change the target `y` parsing in `train_xgboost.py` from a 1D categorical array to a 2D one-hot encoded matrix. Wrap the `XGBClassifier` in `sklearn.multioutput.MultiOutputClassifier`.
  - **Inference**: Update `inference.py` to handle the `predict()` output of the `MultiOutputClassifier` (which is a 2D array) and map any columns predicting `1` back to their respective fault class names.
  - **Isolation Forest**: In `train_isolation_forest.py`, explicitly filter the loaded parquet files or DataFrame to include only rows where `fault_class == "healthy"`. Set `contamination=0.001`.

## Testing Decisions

- **What makes a good test**: Tests should verify the interfaces of the training and inference scripts using small, highly controlled mock datasets, avoiding the need to run multi-hour full training loops just to verify architecture logic.
- **Modules to be tested**:
  - `tests/unit/test_ml_xgboost.py`
  - `tests/unit/test_ml_inference.py`
  - `tests/unit/test_ml_isolation_forest.py`
- **Testing Seams**:
  1. **XGBoost & Inference**: Pass a small, mock multi-label dataset to the XGBoost training function and assert that the returned model is of type `MultiOutputClassifier`. Pass mock inference data to the model and assert that the `inference.py` parsing logic successfully extracts `["sensor_drift", "cylinder_failure"]` when the model outputs multiple `1`s.
  2. **Isolation Forest**: Pass a mock dataset containing both healthy and faulty rows to the training function. Assert that the resulting model flags the faulty rows as anomalies (`-1`), proving that it successfully filtered them out during the `.fit()` phase.
  3. **LSTM**: Assert that `train_lstm_rul.py` completes a single, mocked micro-epoch without raising shape mismatch or NaN errors on the new data structure.

## Out of Scope

- Modifying the underlying physical simulation to generate the data (handled in 04.3).
- Setting up the bulk dataset generation orchestrator (handled in 05.4).
- Changing the core LSTM model architecture or hyperparameters (it just needs a data refresh).

## Further Notes

- The `MultiOutputClassifier` trains one estimator per target column. Ensure the training script preserves the column order (fault names) and saves it alongside the model artifact so `inference.py` can map the outputs back reliably.
