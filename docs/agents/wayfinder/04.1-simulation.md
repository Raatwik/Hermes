# [wayfinder:task] Simulation: Phase 2 (Advanced Data Generation)

## Problem Statement

Following the foundational simulation implementation, gaps were identified between the generated telemetry parameters and the full theoretical set proposed in the `docs/archive/master.md` documentation. The ML and Data Science teams require complete operating context—environmental variables and derived load metrics—to properly contextualize engine behavior. However, these additions must not unnecessarily complicate the core simulation loop or compromise the separation of control inputs from measured engine telemetry.

## Solution

We will extend the simulation API to dynamically derive the missing environmental and operational parameters using established physical approximations, without altering the underlying steady-state maps or adding new lag filters. The International Standard Atmosphere (ISA) model will be used to derive environmental conditions from altitude. Engine load and injection timing will be empirically approximated based on current RPM and throttle. We intentionally restrict our fault catalog to the 5 baseline faults, declining to add more complex mechanical/combustion faults at this stage to keep the baseline data generation stable.

## User Stories

1. As a Data Scientist, I want to query environmental conditions (`ambient_temperature`, `ambient_pressure`, `air_density`) via a separate `get_environment()` API, so that I can contextualize engine performance without mixing environmental truths into the engine's internal telemetry output.
2. As a Data Scientist, I want environmental variables to be automatically derived from the `altitude` control input using the standard ISA model, so that I don't have to manually script complex atmospheric profiles.
3. As an ML Engineer, I want the `get_state()` telemetry to include `engine_load` and `injection_timing`, so that my models have access to these key performance indicators.
4. As an ML Engineer, I want `engine_load` and `injection_timing` to be instantly calculated from current `throttle` and `rpm`, so that they reflect instantaneous operating conditions without the lag associated with thermal measurements.

## Implementation Decisions

- **Control Inputs Separation:** `throttle` and `altitude` will remain strictly as control inputs and will not be output directly in `get_state()`.
- **ISA Environment Model:** A new `get_environment()` method will be added to the `Simulation` class. It will calculate `ambient_temperature` (lapse rate from sea level), `ambient_pressure` (barometric formula), and `air_density` (ideal gas law) dynamically from the current `_altitude`.
- **Dynamic Telemetry:** `engine_load` and `injection_timing` will be calculated inside `get_state()` using empirical formulas based on `throttle` and `rpm`. These do not need new lag filters.
- **Fault Scope:** No new faults (`mechanical_degradation`, `combustion_instability`) will be added. The existing 5 faults (sensor drift, cooling degradation, misfire, injector abnormalities, lubrication issues) are confirmed as sufficient.

## Testing Decisions

- **What makes a good test:** Tests should verify the math of the ISA model (e.g., standard day at sea level yields ~15°C and 101.3 kPa) and the behavior of the new empirical telemetry calculations.
- **Tested Modules:** The `Simulation` class (`get_environment()` and `get_state()`).
- **Test Scenarios:**
  - *ISA Sea Level:* Set altitude to 0, assert `get_environment()` returns standard sea-level values.
  - *ISA Altitude:* Set altitude to 10,000 ft, assert temperature drops to approximately -5°C and pressure drops accordingly.
  - *Engine Load Limits:* Step at 0% throttle, assert engine load is near minimum. Step at 100% throttle, assert engine load is near 100%.

## Out of Scope

- Weather conditions beyond the standard ISA model (e.g., humidity, non-standard temperature days).
- Implementing new fault types beyond the original 5.

## Further Notes

- The ISA environment values will be derived purely algebraically, without storing hidden states across steps. This maintains the purely deterministic and memoryless nature of the environmental conditions.
