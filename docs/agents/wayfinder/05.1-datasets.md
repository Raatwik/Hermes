# [wayfinder:task] Datasets Phase 2: Operational Bounds, Noise, and Environment

## Problem Statement

While the initial dataset generation pipeline (`generate_mission.py` and `generate_datasets.py`) successfully produces partitioned Parquet files with exponential fault degradation and RUL calculation, it lacks the necessary environmental realism and configuration flexibility required by the ML Engineering team. The current setup hardcodes randomization bounds in Python scripts, lacks a sensor noise model, uses completely deterministic physics curves, and tightly couples ambient temperature exclusively to altitude.

To train robust, real-world-ready prognostic models, the pipeline needs to support YAML-driven operational bounds (min/max ranges for phases like Takeoff, Climb, Cruise), inject realistic sensor noise, and allow for independent environmental variables (like ambient temperature) to simulate various weather conditions.

## Solution

Extend the existing simulation and dataset pipeline to support stochasticity and configurable operational envelopes:
1. Refactor the YAML mission parser to accept and sample from `min` and `max` bounds for duration, throttle, and altitude.
2. Introduce a configurable Gaussian noise model to the simulation's telemetry output.
3. Decouple ambient temperature from altitude, allowing the simulation to accept custom weather profiles (e.g., hot day, cold day offsets).
4. Include explicit fault injection metadata (e.g., `time_since_fault_injection`) in the resulting dataset to aid in specific ML prognostic architectures.

## User Stories

1. As a Data Scientist, I want to define base mission phases in YAML files with `min` and `max` bounds for throttle, altitude, and duration, so that the pipeline automatically samples diverse but physically realistic mission profiles.
2. As an ML Engineer, I want the simulation telemetry to include seeded Gaussian noise, so that my models learn to separate true fault signatures from standard sensor inaccuracies.
3. As a Data Scientist, I want to specify an independent `ambient_temperature` (or an offset) for a mission, so that I can generate datasets covering varying climatic conditions (e.g., desert vs. arctic operations).
4. As an ML Engineer, I want the dataset to include an explicit `time_since_fault_injection` column (defaulting to 0.0 prior to injection), so that I can train specialized survival analysis models beyond standard RUL.

## Implementation Decisions

- **YAML Bounds Parsing:** Update `parse_mission_config` in `generate_mission.py` to allow parameters (`throttle`, `altitude`, `duration`) to be specified as either a single float or a `[min, max]` list array. If a range is provided, the parser will sample uniformly between them.
- **Base Mission Assets:** Create standard YAML templates (e.g., `takeoff_cruise.yaml`, `loiter.yaml`) in a new `datasets/missions/` directory.
- **Sensor Noise:** Define a `SENSOR_NOISE_STD` dictionary directly inside `simulation/engine.py` (next to `STEADY_STATE_MAP`). This keeps the physical noise profiles centralized. The `Simulation` class will accept an optional seeded RNG to apply this Gaussian jitter to `get_state()` outputs.
- **Environment Overrides:** Add an `ambient_temp_offset` parameter to the `Simulation` and mission YAMLs. This will be a single mission-level constant offset applied to the entire flight. To generate diverse datasets, allow `ambient_temp_offset` to be defined as a `[min, max]` range in the mission YAML so the orchestrator can sample a random weather offset per run.
- **Metadata Columns:** Add `time_since_fault_injection` during the post-processing phase alongside the `Remaining_Useful_Life` calculation in `generate_mission.py`.

## Testing Decisions

- **What makes a good test:** Tests should verify that the outputs are bounded by the YAML definitions and that noise is consistently applied.
- **Modules Tested:** `datasets.generate_mission`, `simulation.engine`.
- **Test Scenarios:**
  - Mock a YAML config with wide bounds and assert that generated setpoints fall strictly within those bounds.
  - Run the simulation with noise enabled and a constant setpoint, asserting that the standard deviation of outputs matches the configured noise level.
  - Assert that two missions run with different ambient temperature offsets produce distinctly different outputs under otherwise identical conditions.
  - Check the output Parquet file to ensure `time_since_fault_injection` is correct across healthy and faulty phases.

## Out of Scope

- CFD-level aerodynamic or thermodynamic weather modeling.
- Real-time noise filtering (this is a dataset generation feature, not the Digital Twin's observer model).
- Overhauling the core `STEADY_STATE_MAP` (simple environmental offsets are preferred over redefining the entire map).
